# 연차 관리 설정 가이드

직원은 Slack에서 `/연차` 로 신청·조회하고, 관리자는 Slack 버튼 또는 앱의 **인사 → 연차 관리** 화면에서 승인한다.
원본 데이터는 언제나 Supabase(`leave_requests`)이며, 구글 캘린더는 승인된 건을 내보내는 **출력**일 뿐이다.

## 우리 회사 연차 규칙

- 연차는 **정직원에게만** 발생한다. 아르바이트(직원 관리의 구분이 "아르바이트")는 연차·반차를 신청할 수 없고,
  무급휴가·병가·특별휴가만 신청할 수 있다. 연차 현황 탭에도 정직원만 나온다
- 입사 첫 해(1년 미만): 입사일 기준 **1개월 개근할 때마다 1일** 발생 (최대 11일)
- 1년 이상: 직전 연차연도 **출근율 80% 이상이면 15일** 발생
  - 근속 가산: 최초 1년을 초과하는 계속근로 **매 2년마다 1일** 추가, 총 **25일** 한도
    (1·2년 15일, 3·4년 16일, 5·6년 17일 …)
  - 출근율 80% 미만이면 직전 연도에 개근한 달마다 1일
- 개근·출근율은 **연차 관리 → 결근 기록** 탭 기준이다. 기록이 없으면 개근으로 본다.
  승인된 연차·병가·특별휴가·공휴일은 결근이 아니므로 넣지 않는다
- **미사용 연차는 연차연도가 끝나면 소멸**한다 (연도 마지막 날 다음 날이 소멸일)
- 위 계산은 기본값이며, 연차 관리 → 연차 현황에서 연필 버튼으로 직접 지정하면 그 값이 우선한다

### 연차 사용 촉진 (근로기준법 제61조)

| 차수 | 시점 | 내용 |
|---|---|---|
| 1차 | 소멸 **6개월 전** | 미사용 일수를 개인 DM 으로 통보, 10일 안에 **사용 계획 제출** 요청 (DM 의 버튼 → 입력 창) |
| 2차 | 소멸 **2개월 전** | 남은 일수·소멸일 재통보. 계획을 안 낸 사람은 관리자 채널에 "사용 시기 지정 통보 필요"로 올라온다 |

- 남은 연차가 0이면 보내지 않는다. 같은 연도·차수에는 한 번만 보낸다
- 발송 이력·계획 제출 여부는 연차 현황 탭의 **사용 촉진** 칸에서 확인한다
- Slack 이 연결되지 않은 직원은 "DM 실패"로 표시된다 — 이 경우 서면으로 통보해야 촉진 효력이 생긴다
- 2차 때 계획을 내지 않은 사람에게는 회사가 사용 시기를 정해 **서면으로** 통보해야 한다 (앱은 대상만 알려준다)

## 1. 마이그레이션 적용

Supabase 대시보드 → SQL Editor 에 아래 파일을 순서대로 붙여넣고 실행한다.

- `supabase/migrations/018_leave_management.sql` — `leave_requests`, `leave_grants`, `company_holidays` 테이블과
  `employees.slack_user_id` 컬럼, 2026년 한국 공휴일
- `supabase/migrations/021_leave_attendance_promotion.sql` — `leave_absences`(결근 기록),
  `leave_promotions`(사용 촉진 이력)

### 촉진 알림 매일 실행

하루 한 번 아래를 호출하도록 cron 을 건다 (구글 시트 동기화와 같은 `CRON_SECRET` 사용).

```bash
curl -X POST https://tianxia-finance-production.up.railway.app/api/leave/promotion \
  -H "Authorization: Bearer $CRON_SECRET"
```

cron 을 걸기 전에는 연차 현황 탭의 **촉진 알림 확인** 버튼으로 같은 일을 수동으로 할 수 있다.
며칠 빠져도 각 차수 기간 안이면 다음 실행 때 늦게라도 보낸다.

## 2. 직원 정보 확인

**인사 → 직원 관리**에서 각 직원의 **입사일**을 반드시 입력한다. 입사일이 없으면 연차가 계산되지 않는다.
Slack 사용자 ID는 비워둬도 된다 — Slack 표시 이름과 직원 이름이 정확히 같으면 첫 `/연차` 사용 시 자동으로 연결된다.
이름이 다르면 Slack에서 `/연차` 를 한 번 실행해 안내에 나오는 `U...` ID를 직원 관리에 붙여넣는다.

## 3. Slack App 설정

> **이 앱에 `/결제` 를 넣지 않는다.**
> 결제는 슬랙 워크플로우 폼 → 구글 시트 → `/api/sync-sheets` 가 주 경로다.
> `/api/slack/payment` 는 예전에 추가된 보조 직접입력 라우트이고 시트에 쓰지 않으므로,
> 이걸 `/결제` 슬래시 커맨드로 등록하면 팀이 쓰던 워크플로우 폼을 가로채게 된다.

[api.slack.com/apps](https://api.slack.com/apps) → **Create New App** → **From an app manifest**

URL 은 Railway 배포 주소다 (워크스페이스 `tianxia` → 프로젝트 `tianxia-finance` → 서비스 `tianxia-finance`).
도메인이 바뀌면 서비스 → **Settings → Networking → Public Networking** 에서 확인해 세 군데를 함께 고친다.

저장 후 상단의 **Reinstall your app** 을 반드시 눌러야 URL 변경이 반영된다.

```yaml
display_information:
  name: 티엔샤
  description: 연차 신청 및 승인
  background_color: "#1e3a5f"
features:
  bot_user:
    display_name: tianxia   # 봇 핸들(@tianxia)로 변환되는 값이라 한글을 쓸 수 없다
    always_online: false
  slash_commands:
    - command: /연차
      url: https://tianxia-finance-production.up.railway.app/api/slack/leave
      description: 연차 신청 및 잔여 확인
      usage_hint: 12/25 또는 12/25~12/27 사유
      should_escape: false
    - command: /연차현황
      url: https://tianxia-finance-production.up.railway.app/api/slack/leave
      description: 내 연차 현황 (발생·사용·잔여)
      should_escape: false
oauth_config:
  scopes:
    bot:
      - commands
      - chat:write
      - users:read
      - im:write
settings:
  interactivity:
    is_enabled: true
    request_url: https://tianxia-finance-production.up.railway.app/api/slack/interactive
  org_deploy_enabled: false
  socket_mode_enabled: false
  token_rotation_enabled: false
```

`/연차현황` 은 `/연차` 와 같은 URL 을 쓴다 (라우트가 커맨드 이름으로 구분한다).
기존 앱에 추가할 때는 **Slash Commands → Create New Command** 로 위 값을 넣고 **Reinstall your app** 을 누른다.

`should_escape: false` 가 중요하다. `true` 면 Slack 이 입력값을 `<...>` 로 감싸서 날짜 파싱이 깨진다.

만든 뒤 **Install to Workspace** 로 설치하고, 승인용 비공개 채널에 봇을 초대한다 (`/invite @tianxia`).

### 환경변수

Railway → 서비스 → **Variables** 탭 → **Raw Editor** 에 붙여넣는다.
변수를 저장하면 Railway 가 자동으로 재배포하므로 수동 재배포는 필요 없다.

```bash
SLACK_SIGNING_SECRET=...     # Basic Information > Signing Secret (필수)
SLACK_BOT_TOKEN=xoxb-...     # OAuth & Permissions > Bot User OAuth Token
SLACK_LEAVE_CHANNEL=C...     # 승인 카드를 받을 채널 ID (관리자 전용 비공개 채널 권장)
SLACK_LEAVE_APPROVERS=U...   # 승인 버튼을 누를 수 있는 사람 (쉼표 구분, 비우면 채널 전원)
```

채널 ID 는 채널을 만들고 `/invite @tianxia` 로 봇을 초대한 뒤,
채널 이름을 클릭해 맨 아래에서 복사한다. 멤버 ID 는 프로필 → ⋮ 더 보기 → **멤버 ID 복사**.

`SLACK_SIGNING_SECRET` 이 없으면 서명 검증을 건너뛰므로 **누구나 URL만 알면 연차를 신청·승인할 수 있다.** 운영에서는 반드시 설정한다.
`SLACK_BOT_TOKEN` / `SLACK_LEAVE_CHANNEL` 이 없어도 신청은 저장되며, 앱의 연차 관리 화면에서 승인하면 된다.

## 4. 구글 캘린더 연동 (선택)

1. 구글 캘린더에서 "티엔샤 연차" 캘린더를 새로 만든다
2. 설정 → **특정 사용자와 공유** → 서비스 계정 이메일(`...@....iam.gserviceaccount.com`) 추가 → 권한 **"변경 및 공유 관리"**
3. 같은 화면의 캘린더 ID(`...@group.calendar.google.com`)를 `GOOGLE_CALENDAR_ID` 에 넣는다

기존 `GOOGLE_SHEETS_CREDENTIALS` 서비스 계정을 그대로 쓴다. 개인 Gmail 계정이어도 이 방식이면 되고 Workspace 도메인 위임은 필요 없다.

**단방향이다.** 캘린더에서 일정을 지우거나 고쳐도 앱은 읽지 않는다. 취소·반려는 반드시 앱이나 Slack에서 해야 캘린더에서도 지워진다.

## 5. 직원 안내

슬래시 커맨드는 워크스페이스 전체에서 동작한다. 앱을 채널에 초대할 필요가 없고,
아무 채널이나 본인과의 DM 에서 쳐도 되며 **응답은 본인에게만 보인다**(잔여 연차가 남에게 노출되지 않는다).

직원별 준비물은 두 가지뿐이다.
1. 직원 관리에 **입사일** 입력 — 없으면 계산 불가
2. Slack 계정 연결 — 표시 이름과 직원 이름이 같으면 첫 사용 시 자동 연결,
   다르면 직원이 `/연차` 를 한 번 쳐서 나오는 `U...` ID 를 직원 관리에 넣는다

## 6. 사용법

```
/연차                       신청 창 열기 (맨 위에 잔여 연차)
/연차현황                   내 연차 현황 정리 — 발생·이월·사용·잔여·사용 내역 (나만 보임)
/연차 12/25                 하루 신청
/연차 12/25~12/27 가족여행   기간 신청 + 사유
/연차 반차 12/25 오전        반차 (0.5일)
/연차 병가 12/25            병가 — 연차에서 차감되지 않음
/연차 무급 12/25            무급휴가
/연차 취소                  가장 최근 승인 대기 건 취소
/연차 도움말                사용법 보기
```

날짜는 `12/25`, `2026-12-25`, `12월25일`, `오늘`, `내일` 을 인식한다.
주말과 `company_holidays` 에 등록된 공휴일은 자동으로 일수에서 빠진다.

## 연말에 할 일

공휴일은 해마다 바뀐다. **연차 관리 → 공휴일** 탭에서 다음 해 공휴일을 등록해야
연말연시·설·추석이 낀 연차의 일수가 정확하게 계산된다. 2026년치는 마이그레이션에 이미 들어 있다.
